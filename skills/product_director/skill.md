# product_director - 产品演示导演（独立技能）

**把产品功能讲成一段 16:9 演示片：画面用 HTML+GSAP 重建真实产品界面（像录屏但不是录屏）。**

> 与 `director` **完全分开**：`director` 是 PPT/知识讲解叙事线（旁白+分镜+多引擎拼装）；
> 本技能只做产品演示，有自己的分镜规则、运镜原语与两条声音分流，不读也不写 director 的蓝图。

## 摘要
一句话需求 → 分镜蓝图 → **返回 need_confirm 交用户确认** → 带 plan 二次调用 → 逐段写 HTML+GSAP 画面 →
渲染前闸门（结构/运行时/确定性/空白）→ 渲染 → 拼接 → 铺音乐或旁白。

蓝图定稿后**不直接开工**：先返回 `need_confirm` + 分镜表 + 蓝图 JSON，由主 LLM 用 `ask_user`
与用户确认；确认后把蓝图原样作为 `plan` 传回才开始制作（与 `director` 同一套做法）。
用户要改某几镜就改蓝图对应字段后带 `plan` 调用；要整体重做才带 brief + `force=true`。

蓝图被校验打回时**先原地修补**：把报错反灌给模型，它只回"要改哪个字段、改成什么"
（`{"edits":[{"path","value"}]}`），应用到当前蓝图上再校验；连续修不动才整份重写。
画面闸门同理：先回 diff 就地修补，救不回来才整段重写——避免"错一个小字段就重跑几分钟"。
视觉这一步只做**读图兜底**：只问"有没有明显的画面错误"（空屏/黑屏/内容缺失/严重错乱），
可读性、对比度、底部安全区、标题压区都不作为出片判据。
抽帧只判**动画已落位**的帧，黑场/极简暗场直接跳过（每段片头就是淡入黑场，那不是错误），
并且要多数可判帧都异常才判失败——避免少数几帧把成片反复打回。

## 两条分流（`audio_mode`，必须二选一）

| | **bgm**（纯音乐，无旁白） | **vo**（有旁白） |
|---|---|---|
| 叙事 | 文字承担全部信息：章节号 + 大标题 + 副标 | 旁白承担信息，文字只留关键词 |
| 节奏来源 | **先分析音乐**：BPM / 小节 / 能量分段 → 切点对拍 | 旁白实测时长 → 镜头 = 句子长度 |
| 单镜 | 2.5–4.0s，切点误差 ≤0.12s | 句长 ±0.35s，单镜 ≥1.6s |
| 文字 | 每镜必有；字数×0.16+0.8 ≤ 单镜时长 | `title` ≤8 字，`sub` 可空 |
| 运镜 | 可夸张：push-in / pan / whip / tilt / creep | 克制：push-in / pan / creep / static |
| 音轨 | 音乐整曲（裁到成片长度 + 淡入淡出） | 旁白为主 + 低音量垫乐（按人声自动闪避） |

两条分流共用的硬约束：**承载文字的画面，元素落位后必须有 ≥1.2s 静止可读窗口**，这期间相机速度最低。

### 旁白垫乐与自动闪避（`bgm_under_vo`，默认开）
vo 分流下除了旁白，还会垫一层低音量背景音乐，并按人声自动闪避（ducking）：
说话时把垫乐压约 10–12dB，停顿后几百毫秒内自动回到基准音量（0.2），成片首尾各做淡入淡出。

- **素材来源**：用户给了 `music_path` 就用它；没给则按 `music_style` 预设生成，
  并在提示词后追加「垫乐」用途约束（存在感低、避开人声中频、绝不能压住说话）——
  这是"用途层"约束，和选哪种气质正交。
- **不做节奏分析**：vo 的切点跟句子走，不跟拍子走，所以不跑 rhythm，取音乐开头到成片长度。
- **关掉**：`bgm_under_vo=false` 就是纯旁白。
- **失败降级**：垫乐生成不出来时自动退回纯旁白，不阻断出片。
- 实现：`_attach_audio` 里 `adelay → amix(旁白)`，音乐 `volume → afade → apad`，
  再 `sidechaincompress(threshold=0.02, ratio=9, attack=12ms, release=420ms)` 压出来，最后 `amix + alimiter`。
  旁白流要 `apad → asplit` 两路（同一路不能既当侧链又进 amix；不 pad 的话侧链在最后一句断掉，尾巴会死寂）。

## 3D 真机镜头（`stage3d`）

默认画面是 HTML 重建的平面界面窗口。当"这个功能真的跑在手机上／笔记本上"本身是卖点时，
给**个别镜头**写 `stage3d`，系统会真的建一台设备、把真实界面贴到屏幕上，用镜头绕着它拍。

```json
"stage3d": {"device": "phone", "action": "scroll",
            "azimuth": 24, "elevation": 13, "move": {"orbit": 8, "rise": 2, "zoom": 0.94},
            "page": "聊天列表自动向下滚动，停在「林晓」这条会话上"}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `device` | `phone` / `laptop` | **只有这两种外观**。产品是别的硬件（主机/音箱/手表…）就不要写 stage3d |
| `action` | `open` / `scroll` / `push` / `tilt` / `static` | `open` 只有 laptop 可用（开盖）；其余只作运镜缺省值 |
| `azimuth` | 数字 −78~78 | 0=正对屏幕；正值绕到左侧，负值绕到右侧 |
| `elevation` | 数字 −6~46 | 0=平视；正值俯视，能看到机身厚度 |
| `move` | `{orbit, rise, zoom}` | 运镜：绕行角度 / 仰角变化 / 结束距离系数（连续量，不是模板） |
| `page` | 自然语言 | **屏幕上是什么、这一镜里它怎么动**，不是"展示首页"这种空话 |

机位和运镜都是**连续量**：`angle`（`three-quarter`/`front`/`side`）只是三个缺省值，
只写它会让不同镜头的构图完全一样——所以默认要求写数字。

**用量**：全片 2~3 镜、最多不超过一半，且必须**连续排布**（3D→平面→3D 会被校验打回），
单次连拍不超过 3 镜；**连续两镜必须换机位**（方位差 ≥18° 或仰角差 ≥10°），否则两镜画面几乎一样。
3D 拍 `beat_type` 恒为 `ui`，`ui_surface` 留空（不参与界面一致性复用）。

**实现链路**（一个镜头跑一遍，全确定性可复现）：
1. LLM 写屏内页面 `screen.html`——真机尺寸、真实文案、禁止 CSS 动画，状态全部由 `window.render(t)` 算；
2. 无头 Chromium 按 `?t=` 逐帧截图，得到屏幕贴图序列（页面静止时自动只截 1 帧复用）；
3. Blender 用 `skills/blender/scripts/stage3d_scene.py` 渲染：设备模型来自 `devices.py`，
   机位**不是写死的**——量出设备包围点后按视锥反解拍摄距离，所以换机型不用调相机；
4. 标题单独渲成透明 PNG（HTML 截图）叠上去，保证和全片排版语言一致；
5. 编码成 `clip.mp4` 回给主流程拼接；
6. 屏幕贴图序列、Blender 帧序列、标题层都放**系统临时目录**，编码完立即删除——
   项目里只留 `screen.html` 源文件，不堆几十上百张 PNG（与 `director` 的 blender 引擎一致）。

**取景联动**：`title_zone=left/right` 时设备横移让位，`top/bottom` 时设备竖移并缩小；
`laptop` 在 3D 里几乎占满画面，所以 3D 笔记本拍的标题只能用 `top` / `bottom`。

**底色跟随全片（`style.bg`）**：3D 段的背景不是固定的白，而是直接用蓝图里 `style.bg` 的色值，
渲染出来与 HTML 段像素级一致（实测 #0B0D12 → 背景取样 (11,13,18)）。
影棚环境亮度按底色的相对亮度**连续**过渡：深底配暗环境（机身靠灯打出边缘高光），浅底配亮环境；
标题文字的黑白也随底色反转（深底用浅字）。所以不存在"HTML 是深色、3D 段突然变白"的断档。

**上下大标题的景深分层（硬件优先）**：`title_zone=top/bottom` 时，这一镜改用「透明渲染 + 三层合成」：

```
底色(style.bg) → 虚化标题(σ≈3.4@1080p，字号×1.34) → 设备(RGBA，机身常焦)
```

标题因此落在设备的**后面**、处在另一条焦平面上：机身会真正压住字的边缘，观感是"硬件在前、字在后"。
它只是把渲染的 film 改成透明、后期多叠一层，**不增加渲染成本**；代价是需要 `style.bg` 已知（否则退回普通叠字）。

`title_zone=left/right` **不启用**这一层：左右分屏时文字与设备本来就不重叠，虚化只会白白牺牲可读性。

**分段与续跑**：3D 拍和 HTML 拍必须落在不同段（前者整段交 Blender，后者交 HyperFrames），
`_split_segments` 会自动在两者交界处切断。3D 段的内容指纹取自 `scripts/stage3d.py`，
改管线会自动重渲，改文案但镜头没变则复用。渲染预算按 3D 段数单独放宽。

## 音乐节奏分析（bgm 分流）
`scripts/rhythm.py` 用 ffmpeg 解码 + numpy 起音包络：
1. 自相关估 BPM（60–190），抛物线插值；
2. 梳状打分求拍相位，生成 `beats`；
3. 每 4 拍一个小节，选能量最强相位作 `downbeats/bars`；
4. 按 2 秒窗口能量切 `sections`（low/mid/high）。

## 音乐（默认自动生成）
- 用户给了 `music_path` → 直接用整曲（节奏分析照样跑），不擅自截断。
- 没给音乐 → **默认调音乐生成技能**，`instrumental=true`，并从三个气质预设里选一个：
  - `trailer`（默认）：电影预告片气质，庄重史诗、有推进力，段落边界有 impact/drop；
  - `industrial`：工业电子，机械感、金属敲击、门限噪声、冷峻精密；
  - `pulse`：极简科技脉冲，稳定脉冲驱动、克制有力量，适合不抢旁白。
  三者只要求**节奏清晰、稳定、可卡点**，**不限定乐器**：打击乐、合成脉冲、断奏弦乐/钢琴、
  贝斯律动、拨弦等任何能给出明确律动的声部都可以，不必是鼓。共同排除流行歌曲写法
  （主歌副歌结构、旋律 hook、歌词与人声），而不是排除某种音色。
- **自动生成的 BGM 不会整片使用**：它通常 2 分钟以上。现在是**内容优先**：先对整曲做节奏分析，
  蓝图按内容实际需要排镜头（讲完就收尾，成片长度 = 最后一镜的 end），再按成片长度去截
  「节奏最密集」的一段（按段落能量 + 小节首拍 + 含 drop 打分），两头做淡入淡出，
  再对截出来的片段重新分析节奏——切点网格只对真正播放的那段有效。**不再让蓝图凑满音乐长度**。
- `music_prompt` 只用来完全覆盖预设描述。

节奏分析除 BPM / 小节 / 能量分段外，还输出 `accents`（拍点重击强度）与 `drops`（小节能量突增），
两者都会注入提示词：**最大幅运镜与场景切换必须落在 drop 上**，次级动作落在重击拍上。

产物 `audio/rhythm.json`，并把「BPM + 小节表 + 重击/落点 + 能量分段」注入分镜提示词与画面提示词；
LLM 必须按小节起点切镜，不再凭感觉写秒数。没有音乐/解码失败时退回 120BPM 4/4 网格，不阻断出片。

## 参数
- `brief`（string，首次必填）：产品、目标用户、这次要演示的功能动作；二次执行（带 plan）时可省。
- `plan`（string，二次执行时用）：已确认的分镜蓝图 JSON。传入即跳过设计、直接开始制作；
  用户改了哪几镜就改蓝图对应字段再传回。
- `output_path`（string）：成片 mp4；相对路径放 `video_work/<project>/`。
- `project`（string，可选）：项目名。
- `duration_s`（integer，可选）：**内容时长参考上限**；**用户没说就别传**，工具会按要演示的功能动作数自己定（10–90s）。
  它是规模参考不是配额：成片长度由蓝图内容决定（讲完就收尾），配乐会被裁到与成片同样长；
  用户直接给的现成音乐同样只取其中与成片等长的一段。
- `audio_mode`（string，可选）：`bgm`（默认）/ `vo`。
- `music_path` / `music_prompt`（string，可选）：`music_path`=用户指定音乐；不给则默认生成纯 BGM，
  `music_prompt` 仅覆盖默认音乐描述（无人声、隆重、强节奏）。两条分流都会用到：bgm 里是主音轨，vo 里是垫乐。
- `bgm_under_vo`（boolean，可选，默认 true）：vo 分流时是否给旁白垫一层低音量 BGM（自动闪避）；false = 纯旁白。
- `style_prompt`（string，可选）：配色/字体/动效基调；留空由导演定。
- `product_name` / `ui_note`（string，可选）：产品名、界面必须出现的元素。
- `ui_source` / `ui_mode`（string，可选）：真实 UI 来源。给前端工程目录/文件/截图（多个用换行或分号分隔），
  `ui_mode=code`（默认）会抽出设计变量、布局骨架、组件样式与真实资源；
  `shots` 只有截图时会先用读图链路把截图转写成界面规格（栏位比例/控件/配色/层级/可见文案），
  再由模型照着文字重建界面——截图本身不会被贴进画面；
  `hybrid` 两者并用。代码里解析不到样式但目录里有截图时自动降级为 `shots`。
  什么都不给则由模型按 brief 自由还原。
- `width` / `height` / `fps`（integer，可选）：默认 1920×1080@30。

## 断点续跑
同一条任务中断（闸门不过、程序关闭、人工停止）后，**再调一次**即可续跑：
- **续跑只带同一 `project` / `output_path`，不要重复传 `brief` / `plan`**：省略的参数按项目首次调用时的设定继承
  （`audio_mode`、时长、音乐参数、`ui_source` 等都不会回落到默认值）。把蓝图再贴一遍反而容易因 LLM 复述漂移
  触发重排；已经定稿的蓝图是这条任务的真值，不会重新过审，也不会被要求重写。
- **不设整条任务的总时长超时**：带 3D 段的片子跑十几到几十分钟是正常的，卡总预算只会在快完成时把活杀掉。
  真正的卡死由「LLM 连续 N 秒收不到数据」的停滞看门狗兜底，其余靠用户取消。
- **蓝图没被用户确认过就不会开工**：新设计的蓝图先返回 `need_confirm`，带 `plan` 回来才进入渲染；
- 输入指纹相同 → 全量复用：UI 提取（不重跑读图）、时长判定、BGM（不重新生成）、节奏分析、分镜蓝图；
- 输入指纹变了（例如 brief 换个说法）→ 只重排分镜，**已渲染的分段按内容指纹查表复用**：
  索引键是「这一段要画什么」的指纹而不是段序号，所以蓝图多一镜/少一镜导致下标整体错位时，
  内容没变的段仍会被认出并直接拷过来，不会从第一段重渲；
- 分段产物按指纹落盘，同一指纹只渲一次；每渲完一段就写 `product-state.json`，失败不回退已完成部分；
- 旧版本留下的工程（只有 `product-plan.json`、没有 state）也会被识别为续跑起点，沿用其蓝图；
- `force=true` 抛弃全部进度重做。

## 产物
- 成片 mp4
- `product-plan.json`：分镜蓝图（含每镜 start/end、文案、运镜、界面动作）
- `audio/rhythm.json`：BGM 分流才有
- `segments/`：分段画面与 HyperFrames 工程（可单独重渲某段）
- `visual-bible.json`：多段片子才有，按**界面标识**分组（`{"surfaces": {"主工作台": {...}, "设置页": {...}}}`）。
  每块界面第一次出现并定稿后提炼一份，注入它**后面再次出现**的段落；**不同界面之间不复用**，
  各自走 code/shots 读取（同一款产品的不同界面不能互相串样式）。只锁界面外壳与控件语言，
  不锁标题排版与运镜；单段出现过的界面不提炼。

## 边界
- 不做 PPT 式大段文字罗列；不做知识科普（那是 director / manim）。
- 不做真实录屏与屏幕捕获；界面是代码重建的。
- 单段 ≤26s（一次 LLM 写得稳的体量），超长自动按镜头边界切段再拼。
- 旁白只用 narration 部门；音乐只用 music_generate 或用户给的现成文件。
