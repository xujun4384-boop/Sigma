# canvas skill

## 摘要

在 Sigma 绘画画布上作画。模型输出的是**绘图指令**，不是像素也不是坐标阵列：
给少量控制点和图形描述，引擎用真实笔刷把每一笔画出来，用户能看到笔迹逐步生长。

画布逻辑尺寸 `1600 × 1000`，坐标 `(0,0)` 在左上角，`x` 向右，`y` 向下。

包含 2 种工具：

- `canvas_draw` — 按指令在画布上绘制
- `canvas_review` — 审查当前画面，返回问题清单

---

## 标准流程：画 → 审 → 改

```
canvas_draw（先出结构，再上色，最后细节）
    ↓
canvas_review（模型自己看画成什么样）
    ↓
有问题 → remove 删除有问题的笔迹 + canvas_draw 重画
    ↓
再 canvas_review 确认，直到"通过"或达到次数上限
```

**为什么要审**：模型看不见自己画的结果，靠坐标推演很容易出现比例失真、元素错位、
内容冲出画布这类问题。审查相当于给它一面镜子。

**审查分两部分，性质不同**：

| 部分 | 内容 | 可信度 |
|---|---|---|
| 几何审计 | 越界、重复描边、大轮廓未闭合、每个图层的范围与中心坐标 | 坐标算出的数值，**直接采信** |
| 视觉评审 | 画的是什么、比例与形态是否走样 | 观感判断，仅作参考 |

**冲突时以几何审计为准。** 视觉模型会把「没有对齐」说成问题，而实际坐标是对称的——
它无法真的比较坐标。凡涉及位置、间距、是否居中、是否越界，只看几何审计给的数字。

**审查上限**：同一轮任务最多 3 次。达到上限后工具会要求停止迭代、把剩余问题汇报给用户。
不要试图绕过这个限制——连续微调超过 3 轮通常说明结构本身有问题，需要重新构思而不是继续修补。

**审查结果怎么用**：只修正能确证的问题，用 `remove` 删掉对应笔迹再重画。
不要整张重画，那会丢掉已经画对的部分。

## 参数

### canvas_draw

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `commands` | array | 是 | 绘图指令数组 |
| `style` | string | 否 | 画风，由题材决定，默认 `organic` |

### canvas_review

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `focus` | string | 否 | 本次重点检查什么，如「轮子和货厢的比例」。不填则整体检查 |

返回内容：
- 几何审计：画布尺寸、每笔总数、各图层的范围与中心坐标、确证问题（越界 / 重复描边 / 大轮廓未闭合）
- 视觉评审：可辨识度与比例形态问题，最多 3 条

两者的性质与冲突处理见上文「审查分两部分」。

## 画风（style）必须先选

画风不是美术偏好，是**笔刷分配的硬约束**。选错或笔刷与图层用途不符的指令会被拒绝，并返回修正提示。

| style | 题材 | 勾线层（outline） | 上色层（color） | 细节层（detail） |
|---|---|---|---|---|
| `precise` | 车辆、机械、建筑、产品、家具、平面图 | pencil / ink | marker / watercolor | ink / pencil / charcoal |
| `organic` | 动物、人物、植物、风景、食物 | pencil / ink | watercolor / marker | ink / pencil / marker / charcoal |
| `technical` | 流程图、示意图、表格、架构 | ink | marker | ink |

**判断方法**：看画面主体是不是由直线、圆弧、矩形这类规整几何构成。是 → `precise`；有机形态 → `organic`；纯图解 → `technical`。

机械类题材最常见错误是拿水彩描边——宽水彩笔一勾线必然糊成一片雾，所以这条会被直接拦下。

## 指令格式

数组里每个元素是一条指令，按数组顺序执行。共 5 种：

### stroke — 画一笔

```json
{
  "op": "stroke",
  "id": "s1",
  "layer": "outline",
  "brush": "pencil",
  "color": "#3a3733",
  "width": 3,
  "opacity": 1,
  "path": { "type": "curve", "points": [[400, 300], [300, 260], [240, 340]], "smooth": 8 }
}
```

- `id` 必填且全局唯一，后续修正、删除都靠它
- `layer` 不存在会自动创建，但建议先用 `layer` 指令显式声明顺序
- `color` 默认 `#3a3733`，`width` 默认 3（范围 0.4~80），`opacity` 默认 1

### layer — 声明图层

```json
{ "op": "layer", "id": "outline", "name": "线稿", "visible": true, "opacity": 1 }
```

**指令中的先后顺序就是图层上下关系**：先声明的在下层。

### remove — 删除一笔

```json
{ "op": "remove", "id": "s1" }
```

### clearLayer — 清空某层

```json
{ "op": "clearLayer", "layer": "detail" }
```

### clear — 清空整张画布

```json
{ "op": "clear" }
```

## path 原语

优先用图形原语表达形状，**不要写密集坐标点**。点太密会显得僵硬，也浪费输出。

### curve — 自由曲线

```json
{ "type": "curve", "points": [[x1,y1],[x2,y2],[x3,y3]], "smooth": 8 }
```

`points` 是控制点，最少 2 个。`smooth` 为 0~30，引擎做 Catmull-Rom 插值；
**3~8 个控制点最合适**——给关键转折和弧度走向即可，中间由引擎补。

### polyline — 折线

```json
{ "type": "polyline", "points": [[x1,y1],[x2,y2]] }
```

不做平滑，用于尖角、折角、排线。

### bezier — 贝塞尔曲线

```json
{ "type": "bezier", "points": [[起点x,起点y],[控制1x,控制1y],[控制2x,控制2y],[终点x,终点y]] }
```

点数必须是 `1 + 3n`，每三个点一段。适合流畅的长弧线（尾巴、头发、衣褶）。

### ellipse — 圆 / 椭圆 / 圆弧

```json
{ "type": "ellipse", "cx": 800, "cy": 400, "rx": 150, "ry": 120, "from": 0, "to": 360 }
```

- `from` / `to` 单位是度，0 度在三点钟方向，顺时针为正
- 画不闭合的弧就用 `from`/`to`，例如眼睑 `from: 200, to: 340`
- `rotation` 可选，整体旋转角度

### rect — 矩形

```json
{ "type": "rect", "x": 100, "y": 100, "width": 300, "height": 200, "radius": 12 }
```

`radius` 可选，圆角半径。

## 笔刷

| brush | 质感 | 适合 |
|---|---|---|
| `pencil` | 颗粒感、边缘毛糙 | 勾线、草稿、轮廓 |
| `ink` | 硬边、干净锐利 | 最终线稿、眼睛、细节 |
| `marker` | 半透明宽笔画 | 色块、条纹、平涂 |
| `watercolor` | 大面积晕染、边缘柔和 | 背景、大面积上色 |
| `charcoal` | 松散颗粒、灰调 | 阴影、质感、氛围 |

## 构图层级

先想清楚画面有哪几层，再逐层落笔。典型顺序（从下到上）：

1. **背景层** — watercolor 大面积铺底
2. **上色层** — watercolor / marker 铺主体颜色
3. **线稿层** — pencil / ink 勾轮廓
4. **细节层** — ink 画眼睛、纹理，marker 画条纹，charcoal 加阴影

层数按画面复杂度定，简单画面 2~3 层即可，不要为了分层而分层。

---

## 落笔方法

**先大体、后细节。** 每一层内部也遵循这个顺序：先画大轮廓，再修局部。

**一笔一件事。** 一个轮廓一笔画完，不要拆成很多碎笔；不同部位分开下笔。

**用图形原语搭结构。** 圆形的部分用 `ellipse`，对称的部分算出镜像坐标，
弧线用 `bezier`。靠原语保证形状规整，靠笔刷保证手绘质感。

**控制点给"决定形状"的位置。** 一条腿只需要髋、膝、踝三个转折点，
把点布在拐弯处，直线段不用加点。

**用 remove 迭代。** 画错了删除那一笔重画，不要整张重来，也不要靠叠加覆盖来掩盖错误。

## 几何对齐（precise 题材必看）

车辆、机械、建筑这类画面最容易在比例和对齐上出问题。落笔前先算清楚几组关系：

**同心与等距。** 一组轮子要有相同的圆心高度和半径，相邻圆心间距相等。
先确定轮径 `r` 和间距 `gap`，然后逐个 `cx = x0 + i * gap` 算出来，不要凭感觉写。

**水平与垂直。** 同一高度的边缘用相同 `y`；垂直边用相同 `x`。
一条水平边画歪了，整个结构看起来就是塌的。

**宽度分配。** 先定主体总宽，再按功能比例切块。
例如卡车：驾驶室约占 25%，货厢约占 65%，中间留 10% 连接区。
总长不要超过画布宽度的 75%（约 1200px），右侧留边距。

**组件嵌套。** 车窗必须在驾驶室轮廓内部，且四周留白；
门把手在门板上，不能画到轮廓外面。

## 尺寸与位置

画布 `1600 × 1000`，主体建议占据中间区域，四周留出约 10% 的边距。

常见参考：

| 内容 | 建议尺寸 |
|---|---|
| 画面主体（人物、动物） | 宽 400~700，高 500~800 |
| 头部（半身像） | 直径 200~320 |
| 单个物体（杯子、书） | 宽 150~350 |
| 背景大色块 | 覆盖 800×600 以上 |

元素之间保持间距，不要挤在一起，也不要让内容贴边。

---

## 颜色

给颜色用十六进制，同一画面内保持色调统一：

- 主体色 1~2 个主色相，明暗用同一色相的不同明度
- 阴影用比主体色调深、饱和度略低的颜色
- 勾线色不要用纯黑，用 `#3a3733` 这类带暖调的深色更自然
- 大面积浅色上用深色笔画细节，深色区域用浅色提亮

## 自检清单

输出前逐条核对：

1. **画风选对了**：主体是规整几何 → `precise`；有机形态 → `organic`；图解 → `technical`
2. 每条 `stroke` 都有唯一 `id`、`layer`、`brush`、`path`
3. `id` 在整次调用中不重复
4. **笔刷与图层用途匹配**：勾线层不用 watercolor；precise 的主体色块用 marker，水彩只用于大面积背景铺底
5. `path` 用的是原语，控制点数量合理（3~8 个），不是几十个密集点
6. `bezier` 的点数是 `1 + 3n`
7. 先声明了 `layer`，且顺序符合"先底层后上层"
8. 坐标在 `0~1600 × 0~1000` 范围内，右侧留有边距，没有内容冲出画布
9. 同组元素对齐：轮子同高同半径等间距，水平边 y 相同，垂直边 x 相同
10. 颜色有明暗层次，不是一个颜色画满

## 常见错误

| 现象 | 原因 | 修正 |
|---|---|---|
| 笔迹没出现 | `id` 重复被去重，或 `path.points` 少于 2 个 | 换唯一 id，补控制点 |
| 形状僵硬像折线 | 全用 `polyline`，或点太密 | 改用 `curve` 并给 `smooth`，减少控制点 |
| 线条断成几截 | 一条轮廓拆成多笔且端点没对齐 | 合并成一笔，或用相同端点坐标衔接 |
| 画面脏成一片雾 | 用水彩勾线，尤其 precise 题材 | 勾线换 pencil / ink；precise 主体色块用 marker |
| 元素大小不一、位置歪斜 | 凭感觉写坐标，没有先算几何关系 | 先定基准值（轮径、间距、y 基准），逐个算坐标 |
| 内容被上层盖住 | 图层顺序反了 | 调整 `layer` 指令的先后顺序 |
| 画面脏乱 | 笔刷和用途不匹配（如用 charcoal 勾细线） | 勾线用 ink / pencil，上色用 watercolor |
| 元素超出画面 | 坐标算错或尺寸过大 | 缩小尺寸并整体平移回中间区域 |
