# narration - 旁白组（多段配音 + 权威时间轴）

**把多段旁白文案批量转成配音（mp3），并给出权威时长与字级时间戳。** 是「声音部门」，内部调用豆包 TTS 2.0（`doubao_tts`）实现，原理不变。

## 摘要
输入多段旁白文案 → 逐段合成 mp3 → 每段返回 `audio_path` / **实测时长** / 字级 `words`，并汇总 `total_duration`。

## 职责边界（关键）
- **旁白 = 时间基准（timing authority）**：旁白实际读速决定每段时长，**是画面时长的权威依据**——不要预先定死时长，让画面去适配旁白。
- **字级时间戳 = 字幕的唯一时间源**：字幕组据此生成字幕，因此**字幕天然与旁白同步**——"语速↔字幕速度"不需要额外的对齐代码，是一条契约而非一段逻辑。
- **本组不做**：不生成画面、不做字幕排版、不做合成。语速/音量只是"调节旋钮"。

## 时长为什么用实测值
豆包返回的字级时间戳，末字 `endTime` 会**漏掉句尾停顿**（约 0.3~0.9s）。段级累加会漂移，所以每段时长用 **ffprobe 实测 mp3** 为准（取不到时才回落字级末字）。

## 长旁白分块合成（字幕漂移修复）
豆包单次合成超长文本时，数字/英文等"朗读展开"的 token 会拿到极短的时间戳，字级时间轴比实际音频越来越短（实测 50 秒段尾部偏差可达 8 秒），表现为段内字幕逐步提前、段尾没有字幕。

因此本组会把每段文案按句切成 ≤45 字的小块，**逐块合成、逐块以 ffprobe 实测块长定位**，再按真实时长拼接成 `vo_<index>.mp3`：
- 误差被限制在单块内，不再跨块累积；
- 每块做一次以实测块长为锚的**线性重标定**（块短，拉伸幅度小）；
- 漂移超出可校正范围（0.8 倍~1.4 倍）时保留原始时间戳，并在进度里告警（`max_drift` 一并返回，便于排查）。
- 接口不变：字幕组/导演/合成层无需改动。

## 参数
- `segments`（array，必填）：每项 `{"text": "..."}` 或直接字符串，至少 1 段。
- `project`（string）：产物默认放 `video_work/<project>/voice/`。
- `output_dir`（string，可选）：覆盖默认输出目录。
- `speaker`（string，可选）：音色ID；留空用 Settings「配音音色」。
- `speech_rate`（integer，可选，默认0）：统一语速 -50~100。
- `loudness_rate`（integer，可选，默认0）：统一音量 -50~100。

## 输出
```
{
  "segments": [
    {"index": 0, "text": "...", "audio_path": ".../vo_0.mp3", "duration": 3.42, "words": [{word,startTime,endTime}, ...]},
    ...
  ],
  "total_duration": 12.8,
  "segment_count": 3,
  "chunk_count": 7,
  "max_drift": 0.42,
  "speaker": "...",
  "speech_rate": 0
}
```

## 与其它部门的关系
- 上游：无（或由导演给定文案）。
- 下游：**字幕组**消费 `words` 出字幕；**导演/画面部门**用 `duration` 定画面时长；**合成部门**用 `audio_path` 混音。
- 引擎：`doubao_tts`（内部，不直接对外）。

## 依赖
- 豆包语音 API Key：Settings → Skill Keys → 豆包语音生成（`doubaoVoiceApiKey`）。
- 时长实测需要 `ffprobe`（通常随 ffmpeg 一并安装）。
